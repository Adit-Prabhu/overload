## Design invariants
- Game code owns all state. The rival model receives only the observation-filter summary (visible distance and power-use events, allowed tactic catalogue, prior accepted tactic) and returns one proposal: `pressure`, `spacing` or `lateral`, plus evidence IDs.
- Game code validates tactic enum, evidence IDs, session/request/encounter IDs, request cap and deadline. Anything invalid, late, unavailable, disabled or over budget becomes `lateral` (neutral), labelled as fallback in logs.
- Encounter 1 starts neutral. At most one request between encounters 1–2 and 2–3, zero retries, 5 s hard deadline, started in the safe room and never on the frame thread. The tactic freezes on encounter entry. Late replies are ignored. Retrying an encounter reuses its entry loadout, tactic and observation checkpoint with no new call.
- Combat is deterministic for the same inputs, seed and accepted tactic trace, and fully playable with the model disabled.
- The fixed-schedule baseline uses identical arena, moves, stats, unlocks and cues, and never reads observations.
- The model never sees raw world state, hidden inventory, RNG, secrets, other sessions, or tools beyond `select_tactic`. It cannot change stats, unlock items or invent moves.

## Workflow (Adit's standing rules)
Current state, open PRs and next steps: [docs/HANDOFF.md](docs/HANDOFF.md). Read it first and check `gh pr list`, since it is a snapshot.

- One task, one feature branch, one PR. Never commit to `main`.
- After opening a PR, hand it to a fresh read-only reviewer (a separate agent that edits nothing). Fix every finding, or record why not in `docs/DECISIONS_AND_OPEN_QUESTIONS.md`. Push, then comment on the PR listing what was addressed.
- Adit merges, never an agent. Give him the exact commands, `gh pr merge N --merge`, in merge order.
- Stacked PRs: base each on the previous branch, carry fixes forward with merge commits, and state the merge order in the PR body.
- Never force push. Update branches with merge commits.
- Pushes and PRs are authorized. Deploys, credential steps, smoke tests and any paid model call are Adit's: give him the commands (docs/DEPLOY.md).
- Writing: no semicolons and no em dashes in prose, comments, commits or PR text. No co-author or "generated by" lines anywhere.
- Determinism pins: any change to simulation state, `state_hash` or `Tuning` changes the pinned values. Run `uv run python tools/pin_hashes.py` and `uv run --isolated --python 3.11 python tools/pin_hashes.py`. The values must match. Update the tests the tool names, and explain the change in the PR body.
- Before reporting a result: `uv run ruff check .`, `uv run ruff format --check .` and `uv run pytest -q -W error` on Python 3.12 and 3.11. Check visual work by rendering frames with `SDL_VIDEODRIVER=dummy` and looking at them.

## Commands
- Play: `uv run overload` (`--skip-title`, `--seed N`, `--record PATH`, `--replay PATH`, `--condition live|fixed|off`).
- Client checks: `uv run pytest -q -W error`, `uv run ruff check .`, `uv run ruff format --check .`
- Worker: `npm test` in `worker/`. Deploy and smoke test: docs/DEPLOY.md (Adit runs them).
- Audio: `uv run --group tools python -m tools.audio.render` (only changed cues are rewritten).
- Art contact sheet: `uv run --group tools python -m tools.art.contact_sheet`.
- CI: `.github/workflows/overload-checks.yml`, deterministic checks on every PR. Live evaluation is manual and separately authorized.
